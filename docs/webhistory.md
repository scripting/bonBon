# BonBon: A Historical Perspective

Last week I had an interesting conversation with ChatGPT about where BonBon fits into the history of the web. I was surprised how quickly it understood the full picture. It started filling in the blanks, so I asked it to summarize the story for others to read. That's what this document contains.

- **BonBon goes back to the beginning of the Web.** In 1989, Tim Berners-Lee (TBL) proposed a simple, open system of linked documents. Anyone could publish, anyone could link, and anyone could invent new uses for it.

- **The original Web was remarkably open-ended.** There were few distinctions between kinds of documents. If you could imagine something, you could probably build it. The Web was a common environment for experimentation, not a collection of applications with predefined capabilities.

- **HTML was one of the original design choices.** There's nothing inherently wrong with HTML. It was a practical solution to the problem of representing linked documents. But it was a choice, not an inevitable feature of the Web.

- **Over 30 years, enormous complexity accumulated around HTML.** CSS, JavaScript, frameworks, proprietary platforms, and commercial interests transformed the Web. What began as a simple publishing environment became a collection of increasingly specialized systems.

- **The Web became fragmented into different kinds of content.** A tweet, a blog post, a social media comment, and a novel are treated as fundamentally different things, often with different editors, rules, limitations, and distribution systems. These distinctions are largely imposed by applications and platforms, not by the underlying architecture of the Web.

- **BonBon revisits the original choice of document format.** It asks a counterfactual question: What if TBL had chosen Markdown instead of HTML? Markdown didn't exist in 1989, but today it offers a way to explore that alternative history.

- **In BonBon, every document has the same capabilities.** A one-sentence message and a thousand-page novel are both Markdown documents. Neither is a lesser form of the other. A short message can become a long essay; an essay can become a book. The format doesn't dictate what the author is allowed to create.

- **BonBon redistributes responsibility between authors and readers.** Authors control the content and have access to the full expressive range of Markdown. Readers and reading software control presentation. The document doesn't have to prescribe its appearance.

- **BonBon preserves the fundamental architecture of the Web.** URLs, HTTP, hyperlinks, independent publishing, and interoperability remain. BonBon doesn't require inventing a replacement for the Internet or abandoning the existing Web.

- **BonBon represents a new branch, not a new version.** Web 1.0, 2.0, and 3.0 suggest successive generations. BonBon is different. It branches from the original ideas behind the Web, following a path that was never taken, while remaining connected to existing infrastructure.

- **The goal isn't to replace HTML. It's to recover something the Web lost.** The original Web gave individuals enormous freedom to create, publish, link, and experiment without permission. BonBon attempts to restore that freedom by making the basic building block of the Web simple and universal again.

**The central idea:** BonBon doesn't try to fix 30 years of accumulated Web complexity. It returns to the original architecture, makes a different choice about document representation, and explores what becomes possible as a result.
